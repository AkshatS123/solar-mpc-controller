## What this project is

Public reference implementation of the receding-horizon MPC behind the
[Tesphase](https://tesphase.co) v2 charging algorithm. Convex QP in
`cvxpy` (CLARABEL), rolling-horizon simulator, Greedy + ToU baselines for
honest comparison.

Public repo: https://github.com/AkshatS123/solar-mpc-controller

## Working conventions

- **Package manager:** `uv`. Never `pip install` directly.
- **Python:** ≥ 3.11, type-hinted.
- **Tests:** `uv run pytest -q` — all green before any commit.
- **Lint:** `uv run ruff check .` — all green before any commit.
- **Plots:** never edit PNGs by hand — regenerate via
  `uv run python scripts/plot_walkthrough.py`.
- **Synthetic data:** committed under `data/synthetic/`; recorded /
  customer traces are gitignored (`data/raw/`) and never touch this repo.
- **Commit style:** Conventional commits (`feat:`, `fix:`, `chore:`,
  `docs:`). One phase per commit when scoped tightly.

## Common commands

```bash
uv sync                                    # install deps
uv run pytest -q                           # run tests
uv run ruff check .                        # lint
uv run python scripts/run_demo.py          # 3-controller comparison
uv run python scripts/plot_walkthrough.py  # regenerate figures
uv run solar-mpc run --controller mpc      # CLI
```

## What NOT to do here

- ❌ Add Tesphase customer data, OAuth tokens, or anything from the
  private Tesphase repo. This repo is public.
- ❌ Add online demo / web server. That's out of scope (anti-goal in the
  strategic plan).
- ❌ Add ML controllers — those go in the planned `tsfm-imitation-policy`
  repo, not here.
- ❌ Edit `Phased milestones` in this file when a phase closes — update
  the strategic plan in the vault and let this file fall out of sync
  intentionally until the next refresh.
